# 研序私有化试点服务包

版本：v1.0.0。本文是可用于客户沟通的固定范围试点方案；价格是待验证报价，不代表已有成交、收入或市场定价。

## 目标客户与购买理由

研序面向已经使用 GitHub、CI 和 Coding Agent 的 5–50 人研发团队。开发者使用任务合同、团队 Policy、受控生成和 PR/CI 证据；技术负责人购买的是私有部署、范围控制、过程审计、试点验收和可核算的支持成本。

客户现有模型仍负责代码能力。研序解决“AI 可以改哪些文件、应运行哪些测试、当前证据是否对应最新 commit、失败是否阻断、试点是否真正节省人工时间”这些交付治理问题。

## 四周实施流程

1. 第 1 周：确认仓库、任务类型、允许路径、测试命令、数据边界和基线记录方法。
2. 第 2 周：部署 FastAPI、PostgreSQL、Worker 和团队工作台，配置组织权限与 GitHub 接入。
3. 第 3 周：运行真实任务，记录 PR/CI、失败、返工、支持时间和实际成本。
4. 第 4 周：逐项 UAT，导出试点 ZIP 和打印验收报告，双方按合同流程确认是否续费。

## 输入、处理、工具和输出

- 输入：客户批准的仓库、PR、组织成员角色、Policy、验收标准、证据引用和实际成本。
- 处理：组织隔离存储、版本绑定、确定性规则检查、隔离测试、Webhook 队列、审计与报告生成。
- 工具：本地 CLI、Codex 或其他授权 Agent、GitHub/`gh`、Docker Compose 和 PostgreSQL。
- 输出：任务与策略证据、PR/CI 状态、团队看板、审计 JSON、试点 ZIP、可打印验收报告。

平台不自动批准 PR、merge 或部署。客户代码、diff、PR 正文、CI 日志、签名文件和凭据不进入公开仓库；私有服务只保存文档明确列出的标准化字段。

## 验收与续费判断

技术验收要求：服务健康、组织隔离、owner/viewer 权限、GitHub 事件去重、证据导出哈希可复算、备份恢复通过、动态内容转义、Linux/Windows CI 通过。

业务验收由试点前约定的条目决定。提效只在至少 5 个同范围、两侧质量均通过的真实配对任务上计算：

`人工时间减少率 = (基线人工分钟 - 研序人工分钟) / 基线人工分钟 × 100%`

样本不足、质量不一致或缺少证据时保持 `NOT_MEASURED`。`20%` 只能作为待验证目标，不能写成已实现结果。

续费选项可以是季度升级支持、按仓库的团队许可证或后续托管服务。是否建设订阅和 SaaS，取决于真实试点的使用频率、支持成本和付费续约证据。
